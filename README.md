# 日文背單字 App

跟桌面上的「背單字App」（英文／多益版）**同一套架構、完全獨立的兩個資料夾**。
進度各存各的，互不影響。

在電腦上雙擊 `index.html` 就能開；手機請用下面的網址（不需要安裝任何東西、不需要網路，發音除外）。

---

## 手機上怎麼用

線上網址（GitHub Pages，電腦關機也能開）：

**https://brady1011.github.io/jlpt-vocab-app/**

- **iPhone**：一定要用 **Safari** 開，然後「分享 → 加入主畫面」。
  用 Chrome for iOS 加出來的捷徑沒有離線能力。
- **Android**：用 **Chrome** 開，選單 → 「加到主畫面／安裝應用程式」。

加完就有圖示、沒有網址列、離線也能背（第一次開要連網把字庫抓下來）。

進度是存在各裝置自己的瀏覽器裡（`localStorage`，key `jlpt_vocab_v1`），
**手機和電腦不會同步**。要搬進度就用 App 內「設定 → 匯出進度備份」，
再到另一台「合併匯入」。跟多益版（key `toeic_vocab_v1`）也是完全分開的兩份進度。

### 改完內容要做兩件事

只做第一件，手機會一直看到舊版：

1. `git add -A && git commit -m "..." && git push`，推上去約一分鐘 GitHub Pages 就重新發佈。
2. **把 `sw.js` 最上面的 `const CACHE = 'jlpt-vocab-vN'` 往上加一號。**
   這個 Service Worker 是 cache-first 的，不換 cache 名稱舊快取就不會被淘汰。

`sw.js` 只在 https 或 localhost 下才會註冊，所以在電腦上用 `file://` 雙擊開啟時它不生效——
這是正常的，不是壞掉。

## 從英文版改了什麼

評估時實測出來、非改不可的只有幾處，其餘 16 個區塊（間隔重複排程、累積複習、
模擬測驗、錯題本、搜尋、備份匯入、PWA、側邊選單）**一行都沒動**：

| 位置 | 英文版 | 日文版 |
|---|---|---|
| `blankOut()` 挖克漏字 | 用 `\b` 抓單字邊界 | **不能用 `\b`** —— 日文全是「非文字」，`\b会議` 永遠比對不到（實測 false）。改成直接比對＋去語尾取語幹 |
| `speak()` | `en-US` | `ja-JP`，而且唸的是**假名**（漢字多音字才不會唸錯） |
| `.en` 字型 | Consolas | 改名 `.jp`，換成 Yu Gothic / Noto Sans JP |
| 新增單字驗證 | 只收 A–Z | 收假名和漢字，另外強制填假名讀音 |
| 「拼字」題 | 打英文單字 | 改成**「拼假名」**：看中文和漢字，把讀音打出來（桌機不用切輸入法打漢字） |
| 例句長度驗證 | 算單字數 | 算**字元數**（日文沒空格，`split()` 永遠回 1） |

新增的東西：

- **`kana` 欄位** → 漢字上面用瀏覽器原生的 `<ruby>` 標假名，不用外掛
- **`level` 欄位（N5–N1）** → 字庫瀏覽和測驗都能只挑一級來練
- **活用練習**（英文版沒有的模組，見下面）

## 活用練習（英文版沒有的）

英文的 `acquire → acquired` 用字根切片就解決了。
日文的 `食べる → 食べます／食べて／食べた／食べない` 是一整套規則，
而且是日文學習者真正天天在練的東西，所以獨立成一個模組。

**這個題庫是 0 筆手寫內容。** 干擾選項是用**錯誤的規則**算出來的：

> 「書く」的て形，正解是 **書いて**。
> 干擾選項自動產生：**書きて**（直接接て）、**書って**（う・つ・る 組的規則）、
> **書んで**（む・ぶ・ぬ 組的規則）—— 剛好就是初學者最常犯的三種錯。

所以字庫加愈多動詞，題目就自動變多，不必再寫題。目前 6503 字裡有 1362 個動詞／い形容詞可以出活用題，還有
い形容詞可以練。

答錯時會告訴你**為什麼**：「五段動詞、語尾是「く」，て形換成「〜いて」」。

支援的活用形：ます形／て形／た形／ない形。
規則表也直接列在頁面上（一段、五段九組、い形容詞、不規則）。

**特別處理過的例外：**
- `行く` 的て形是「行って」不是「行いて」
- `ある` 的ない形是「ない」不是「あらない」
- `する`／`来る` 整組不規則
- `勉強する` 這類複合動詞

## 字表來源

```
python build_ja.py check    # 只驗證，不寫檔
```

**每一句都要挖得出克漏字空格**（跟 `index.html` 的 `blankOut()` 同一套邏輯）。

### 回頭把 N5–N3 也對齊官方清單（最後一輪）

N2／N1 是一開始就照官方清單選字，但 **N5–N3 當初是我自己想的**。
全部做完後回頭 diff，才發現這三級跟官方表的重疊只有 58–78%：
`好き`、`赤`、`一`、`九`、`家庭`、`後`、`舌` 這種最基本的字根本沒收。
N3 特別低（58.7%），因為我「自己想的 N3」大量落在實際的 N2 範圍。

補了 1221 字之後又踩到一個量測陷阱：我一度用「詞形**或**假名相同」算覆蓋率，
得到 99.6%，但那會把同音異字誤算成已收 —— `厚い`／`暑い`／`熱い` 都是 あつい，
有其中一個不代表另外兩個也有。改用**嚴格詞形比對**後真實數字是 90.2%，
還缺 525 字，再補完才到現在的 96.4%。

剩下的 3.4% 差距全是**寫法差異**（`終る`／`終わる`、`御飯`／`ご飯`、`綺麗`／`きれい`），
同一個詞已經以另一種寫法收在字庫裡；把假名也算進去是 99.8%。

過程中還處理了一類新問題：**同一個漢字有兩個讀音、卻是兩個詞條**
（`位`＝い「第…名」vs くらい「程度」、`市`＝し「城市」vs いち「市集」、
`後`＝ご「…後」vs あと「之後」、`一`＝いち「數字」vs ひと「一…」）。
字庫用 `word` 當唯一鍵，所以每組只能留一個 —— 留常用的那個，
`位`→`くらい` 則改用假名寫法讓兩個都留住。

## 想自己加文法單元

編輯 `data/grammar.js`，照著現有格式加一個物件就好。
格式跟英文版**完全一樣**（`stem` 挖空 ＋ 四選項 ＋ `ans` ＋ `why`），
一行都沒改 —— 這個殼子跟語言無關，只換內容。

```js
{
  id: "keigo",                     // 英文代號，不能跟別的單元重複
  point: "敬語",
  subtitle: "尊敬語與謙譲語",
  explain: [ { h: "小標題", b: "說明內容" } ],
  questions: [
    { stem: "先生が資料を ______ ました。",
      opts: ["ご覧になり", "拝見し", "見られ", "お見し"],
      ans: 0,                      // 正解在 opts 裡的位置（0 開始）
      why: "對老師的動作用尊敬語「ご覧になる」。" }
  ]
}
```

存檔、重新整理網頁就出現了，`index.html` 不用改。
選項在畫面上會自動洗牌，所以正解放第幾個都沒差。
